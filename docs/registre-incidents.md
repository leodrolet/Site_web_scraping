# Registre des incidents de confidentialité — ProspectB2B

> Obligation de la **Loi 25** (art. 3.8). Tenir un registre de tous les incidents
> de confidentialité (accès, utilisation, communication ou perte non autorisés de
> renseignements personnels), qu'ils présentent ou non un risque de préjudice
> sérieux. À conserver **au moins 5 ans**. À fournir à la Commission d'accès à
> l'information (CAI) sur demande.

## Que consigner pour chaque incident

| Champ | Description |
|---|---|
| N° | Identifiant de l'incident |
| Date de l'incident | Date de survenance (ou plage) |
| Date de découverte | Quand l'incident a été constaté |
| Description | Nature de l'incident (accès non autorisé, perte, fuite, etc.) |
| Renseignements visés | Catégories de RP concernées (courriels, mots de passe hachés, historique…) |
| Personnes concernées | Nombre et catégories de personnes touchées |
| Cause | Origine probable (erreur humaine, faille technique, tiers…) |
| Risque de préjudice sérieux | Oui / Non + justification (sensibilité, probabilité d'utilisation malveillante) |
| Mesures prises | Confinement, correction, réduction du risque |
| Avis aux personnes | Oui / Non + date (obligatoire si risque de préjudice sérieux) |
| Avis à la CAI | Oui / Non + date (obligatoire si risque de préjudice sérieux) |
| Mesures préventives | Pour éviter la récurrence |
| Statut | Ouvert / En traitement / Clos |

## En cas d'incident — marche à suivre rapide
1. **Contenir** : stopper la fuite/l'accès (révoquer clés, sessions, corriger la faille).
2. **Évaluer** le risque de préjudice sérieux (sensibilité des RP + probabilité d'usage malveillant).
3. **Consigner** l'incident dans ce registre (même sans risque sérieux).
4. Si **risque de préjudice sérieux** : aviser sans délai les **personnes concernées** et la **CAI**.
5. **Prévenir** la récurrence et documenter les mesures.
